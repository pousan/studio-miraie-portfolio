## 1. 設計方針・状態

カフェ店主のスマホ閲覧を最優先とする。デモ→制作内容→料金・条件→相談という判断を助ける。信頼は料金と所有権の透明性で作る。実績数、口コミ、売上効果、経歴、架空の連絡先を作らない。

現在は開業準備中。問い合わせ・契約・決済の実受付はない。計画中の定員は「先着3店を予定」、状態は「開業準備中・受付開始前」と統一し、「残り3枠」「募集中」としない。ひより珈琲は「架空のカフェを題材にした自主制作デモ」と明記する。記事の実公開日は不明のため捏造しない。

本書の価格以外の具体的な支払・修正・保守条件は設計上の提案である。以下の文案で実装し、販売開始前に事業者が確定する。個人情報プレースホルダを残した状態で受注を開始しない。

## 3. デザインシステム

### 色とコントラスト

| トークン | 値 | 用途 |
|---|---|---|
| --bg | #FAF7F2 | 全体 |
| --text | #1C1917 | 本文・見出し・ボタン背景・末尾帯 |
| --accent | #A16207 | 英字ラベル・タグ・リンク・フォーカス |
| --surface | #FDFCFA | カード・フォーム面 |
| --muted | #5C554E | 注記・補助文字 |
| --border | #D8D2C8 | 装飾罫線 |

相対輝度計算による文字コントラスト比：text/bg 16.37、text/surface 17.06、muted/bg 6.86、muted/surface 7.15、accent/bg 4.61、accent/surface 4.80。すべての文字に4.5:1以上を適用。黒背景の文字はbg。ゴールドを黒の上に載せない。文字のopacityを下げない。入力枠はmutedで描き、borderは装飾線専用。リンクは下線付き、色だけで操作を示さない。hoverも同じ検証済み配色の反転を使用する。

### 書体・寸法

```css
--font-serif: 'Yu Mincho', 'Hiragino Mincho ProN', 'Noto Serif CJK JP', serif;
--font-sans: -apple-system, BlinkMacSystemFont, 'Hiragino Kaku Gothic ProN', 'Yu Gothic', Meiryo, sans-serif;
```

OS搭載フォントのみ。Webフォント、フォントファイル、外部読み込み禁止。日本語見出し・ブランドは明朝、本文・英字・数値・操作はゴシック。

本文16px/1.9、補足14px/1.75、タグ・小ラベル12px/1.5を下限とする。H1はスマホ32px、768pxで40px、1280pxで56px。H2は26/32/40px、H3は20〜24px。大英字は32/52/80px、600、字間.04em。価格40〜56px、日付の月日36〜44px、年14px。本文幅最大38em。長い英字は単語で折り返し、固定幅を与えない。

余白：4/8/12/16/24/32/48/64/80/112px。セクション間64/80/112px、カード内24px（320pxは20px）。角丸0〜4px、影なし、細い罫線、写真に文字を重ねない。

ONCAの文法：大きな英字ラベル＋日本語見出し、枠線付きカテゴリタグ、独立した年と月日、罫線で組む編集グリッド、全ページ末尾のCTA帯。反復英字アニメーション、架空アーカイブ、実績数字による演出は使わない。ひより珈琲run5の配色と余白・明朝の方向性を引き継ぐ。

### レスポンシブ

| 幅 | 指定 |
|---|---|
| 320px | 左右16px、本文幅288px。全体1列。ボタン全幅。料金と税込注記は別行。 |
| 375px | 左右20px、本文幅335px。1列。タグと日付は収まる範囲で横並び。 |
| 768px | 左右32px。ヒーローは7:5、料金・記事は2列。3枚目は通常幅1枠。 |
| 1280px | 最大1120px、左右80px。12列gap24px。ヒーロー7:5、料金・記事は3列。 |

mobile-first。min-width:375/768/1024/1280pxで差分適用。1024px以上は横ナビ、それ未満はメニュー開閉。ヘッダーは通常フローで非固定。開閉ボタン「メニュー／閉じる」、aria-expanded、aria-controlsを連動。展開ナビはヘッダー下に配置。Escapeで閉じボタンへ戻し、リンク選択でも閉じる。JS無効時はナビを展開表示する。

タッチ領域44px以上、間隔8px以上。focus-visibleはaccentの2px枠＋3pxオフセット、黒帯はbg枠。各ページh1は1つ、DOMはスマホの読み順。grid子min-width:0、画像max-width:100%、長文overflow-wrap:anywhere。200%拡大で欠落なし。アニメーションは色変化150msのみ、prefers-reduced-motionでは無効化する。

ラベル付きの4項目：「お名前（デモ用・必須）」text/max80、例「サンプル店主」。「メールアドレス（デモ用・必須）」email/max254、例「sample@example.com」。「お店の名前（任意）」text/max100、例「サンプルカフェ」。「ご相談内容（必須）」textarea/max2000、例「ホームページに載せたい内容をご記入ください。」。placeholderをラベル代用にしない。autocomplete=off。

ボタンはtype=button「入力内容を確認する（送信されません）」。正常時role=statusに「入力内容を確認しました。これはデモのため、送信・保存は行っていません。返信はありません。」。エラーは各項目下に「お名前を入力してください。」「メールアドレスの形式を確認してください。」「ご相談内容を入力してください。」。aria-invalid、aria-describedbyを連動し、最初の不正項目へフォーカス。入力値の再表示は不要。

入力とボタンは初期disabled、JSで送信抑止と検証処理の登録後に有効化。formは入力name・外部actionなし。submitイベントをpreventDefaultしEnter送信も防ぐ。noscript「フォームのデモ操作にはJavaScriptが必要です。入力内容の送信は行いません。」。fetch/XHR/sendBeacon、Cookie/storage、入力のログ記録は禁止。
