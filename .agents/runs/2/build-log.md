# Build Log: 無料セルフチェック（診断フロー）実装

## 1. やったこと

1. **`site/shindan.html` の新規作成**
   - `research.md` §3・§4 の仕様に従い、単一HTML内の画面切り替えによるステップ型セルフチェック（入口画面 → 1問1画面の質問ステップ → 結果画面／回答見直し画面）を実装。
   - 検証用属性として、各画面・質問パネルに `data-step`（`intro` / `question` / `Q1`〜`Q7` / `review` / `result`）、各選択肢（`label` およびネイティブ `input[type="radio"]`）に `data-q` / `data-value` を付与。
   - `fieldset`・`legend`・ネイティブ `radio`・`label`・`button` を使用し、初期選択なし、未選択時のその場でのエラー表示（「選択肢を選んでください。わからない場合も選べます」）、JS無効時の `<noscript>` 案内を実装。
   - 結果画面に免責文（「これは回答に基づくセルフチェックです。サイトの実測・検索順位の確認・専門家による個別調査は行っていません。」）、総合スコアなしの3区分（「回答上、整っていること」「まず見直すこと」「まだ確認していないこと」）、操作ボタン（「結果をコピー」「回答を見直す」「最初からやり直す」「印刷／PDF保存」）、主CTA（`index.html#contact`）・副CTA（`index.html#pricing`）・モニター案内文を配置。

2. **`site/js/shindan.js` の新規作成**
   - 純粋関数 `evaluate(answers)` を実装し、回答コードのみから結果オブジェクトを生成。
   - `Q1=site` のときのみ `Q2` を表示（全7問）、それ以外は `Q2` を省略して全6問に更新し、表示上の質問番号を振り直すとともに省略理由を表示。`Q1` の回答を `site` 以外へ変更した際は不要となった `Q2` の回答を即時破棄。
   - 「まず見直すこと」の優先順を `Q3`・`Q4` → `Q2`・`Q6` → `Q5`・`Q7` とし、最初の表示を最大3件、4件目以降の残りも隠さず一覧表示する構成を実装。
   - `Q1` がホームページなし（`social` / `none`）の場合は既存媒体で基本情報を揃える提案を表示し、`unknown` のみの場合は不備と断定せず「まず現状を確認しましょう」を表示、すべて良好な場合は「今回の回答では、優先して直す項目は見つかりませんでした。」を表示。`delegate` は「更新の依頼先あり」として良好項目に含め、`unused`・`notneeded` は減点・警告なしとした。
   - `sessionStorage` への回答コード保存（失敗時はメモリのみで継続、リセットで消去）および History API（`pushState` / `popstate`）による画面内・ブラウザ戻る操作の整合を実装。外部通信は一切追加していない。

## 4. 検品指摘の修正（2026-11-08）

`.agents/runs/2/check-log.md` の項目9・10の指摘4件を `site/js/shindan.js` にて修正した（質問文・分岐・結果ルール・文案は変更なし）。

- **【10-A】未回答のまま結果が表示される経路の遮断（高）**
  - `getFirstUnansweredQuestionId(answers)` を追加し、画面遷移の共通経路 `showStep`（通常進行・見直し再計算・見直しキャンセル・`popstate`・再読み込み復元）で `result` へ入る際に表示対象全問の有効回答を検証し、未回答があれば最初の未回答設問へ戻すよう修正（質問ステップでも対象設問より前に未回答があれば最初の未回答設問へ戻す）。
  - `loadStateFromStorage` でも復元時に「`result`＋未完了の回答」を検証して最初の未回答設問へ補正するよう修正。
  - セッション世代 `state.generation` を導入して `history.state` と `sessionStorage` に保持し、「最初からやり直す」実行時に世代をインクリメントしてリセット前の履歴エントリを `popstate` で無効化（入口画面へ置換）するよう修正。
  - `evaluate(rawAnswers)` でも有効回答の完了判定（`isComplete` / `unansweredIds` / `firstUnansweredId`）を行い、未回答時は `statusType: 'incomplete'` として `all_good`（「今回の回答では、優先して直す項目は見つかりませんでした。」）と明確に区別するよう修正。
- **【9-A】見直しで Q2 を自動回答しない（中）**
  - 見直し画面（`renderReviewScreen`）で `Q1` を `site` へ変更した際に `state.answers.Q2 = 'unknown'` を自動設定していた処理を削除し、未選択状態で表示するよう修正。未回答のまま再計算・結果へ戻る操作を行った場合は `Q2` の質問画面へ案内する。
- **【9-B】見直し画面の再描画でフォーカスを失わない（中）**
  - `updateReviewQuestionSelection(qId)` を追加し、表示対象設問の構成が変わらない通常の回答変更ではコンテナ全体を再生成せず該当問の選択状態（`checked` / `.is-selected`）のみを更新してフォーカスを維持するよう修正。
  - `Q1` の分岐変更により `Q2` の表示有無・質問番号が変わり再描画が必要な場合も、再描画後に操作した `input[type="radio"]` へフォーカスを復帰させるよう修正。
- **【10-B】画面内の「戻る」とブラウザ履歴の整合（中）**
  - 履歴スタック位置（`historyStack` / `historyIndex`）を追跡する `navigateBackOrReplace` を実装し、画面内の「戻る」（および見直しキャンセル）で直前のブラウザ履歴エントリが戻り先と一致する場合は `history.back()` で履歴を戻し、一致しない場合も `replaceState` で置換することで履歴を積み増さないよう修正（`Q1 → Q2 → Q3 → 画面内戻るでQ2 → ブラウザ戻るでQ1` となることを確認）。
  - 分岐変更（`Q1 !== 'site'`）で無効になった `Q2` の履歴エントリを開いた場合の戻り先を分岐元の `Q1` と定義し、あわせて履歴状態を `replaceState` で `Q1` に更新するよう修正。
